# SLGS Digital Platform

Welcome to the **Sierra Leone Grammar School (SLGS) Digital Platform** technical documentation and handover portal.

The SLGS Digital Platform is built as a production-quality monorepo containing three intentionally separated applications alongside shared domain libraries and infrastructure packages.

---

## Vision & Objectives

The platform modernizes the public web presence of Sierra Leone Grammar School while introducing a dedicated, secure Content Management System (CMS) for editorial governance and student club participation.

### Core Problems Solved

1. **Decoupled Public Communication**: Routine website content updates do not require developer intervention or code changes.
2. **Student Content Moderation**: Controlled publishing capabilities are provided to student clubs (e.g. Multimedia Club, News Journal Club) with mandatory review and approval steps.
3. **Private CMS Operations**: Identities, drafts, workflow history, audit data, and private media metadata are strictly isolated from the public website.
4. **Canonical Path & SEO Integration**: Automatic canonical URL mapping (`/news/:slug`, `/events/:slug`, `/gallery/:slug`, `/announcements/:slug`, `/:slug`) and dynamic sitemap generation.

---

## Product Principles

- **Separation of Concerns**: Keep public communication and private administration strictly decoupled across applications.
- **Default Deny**: Administrative data and CMS endpoints are private by default. UI hiding is not security; all authorization is enforced server-side.
- **Moderated Publishing & Independence**: Student-generated content must pass through a 5-stage workflow (`draft` → `submitted` → `in_review` → `approved` → `published`). Authors cannot review or approve their own work (`independentActor`).
- **Security Barrier Views**: The public web app (`apps/web`) queries read-only PostgreSQL views (`public_content.*`) that project **only** published content with a publication timestamp (`WHERE state = 'published' AND published_at IS NOT NULL`).
- **Auditability**: All sensitive administrative actions, publishing workflow state changes, identity/permission mutations, and asset lifecycle events maintain append-only audit trails.
- **Boring Technology**: Prefer understandable, type-safe, maintainable stack choices (React 19, TypeScript, PostgreSQL, Drizzle ORM, Better Auth) over unnecessary runtime complexity.

| Application | Path | Target Audience | Primary Function |
| :--- | :--- | :--- | :--- |
| **Public Website** | `apps/web` | Prospective students, parents, alumni, public | Read-only public portal (news, admissions, academics, school life) |
| **Content CMS** | `apps/cms` | Multimedia Club, News Journal, Content Editors, CMS Admins | Private editorial application for publishing public site content |
