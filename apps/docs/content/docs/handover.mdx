# Developer & Operations Handover

The active SLGS platform consists of the anonymous Public Web (`apps/web`), authenticated CMS (`apps/cms`), and technical documentation portal (`apps/docs`).

## Prerequisites

- Node.js `>= 24 < 25`
- pnpm `>= 10 < 11`
- PostgreSQL 16+ or compatible managed PostgreSQL
- A private Cloudflare R2 bucket

## Runtime Separation & Database Roles

The Web runtime receives only `WEB_DATABASE_URL` and `PUBLIC_SITE_URL`. It connects using the restricted `slgs_web` database role with read-only access to `public_content` views (`WHERE state = 'published' AND published_at IS NOT NULL`). It receives no Better Auth or R2 credentials.

The CMS runtime receives `CMS_DATABASE_URL`, Better Auth configuration, email configuration, and bucket-scoped R2 credentials.

CMS authorization is identity → active CMS membership → club/organisation scope → active CMS role → permission. Server-side checks enforce self-action suppression (`independentActor`): authors cannot review or approve their own content. Every sensitive mutation is authorized and audited.

## Local Verification Commands

```bash
pnpm check
pnpm test
git diff --check
```

Do not run production migrations from an application runtime credential. The Senior Software Engineer must approve backups, retention, migration execution, post-migration SQL verification, authenticated browser verification, R2 checks, deployment, DNS, and TLS.
