# Developer & Operations Handover

The active SLGS platform consists of the anonymous Public Web, authenticated CMS, and technical documentation application.

## Prerequisites

- Node.js `>= 24 < 25`
- pnpm `>= 10 < 11`
- PostgreSQL 16+ or compatible managed PostgreSQL
- A private Cloudflare R2 bucket

## Runtime separation

The Web runtime receives only `WEB_DATABASE_URL` and `PUBLIC_SITE_URL`. It has read-only access to `public_content` projections and receives no Better Auth or R2 credentials. The CMS runtime receives `CMS_DATABASE_URL`, the Better Auth configuration, email configuration, and bucket-scoped R2 credentials.

CMS authorization is identity → active CMS membership → club/organisation scope → active CMS role → permission. Every sensitive mutation is authorized on the server and audited.

## Local checks

```bash
pnpm check
git diff --check
```

Do not run production migrations from an application runtime credential. The Senior Software Engineer must approve backups, retention, migration execution, post-migration SQL verification, authenticated browser verification, R2 checks, deployment, DNS, and TLS.

See the repository runbooks `docs/21-operational-verification-runbook.md` and `docs/26-cms-operational-verification-checklist.md` for the controlled procedure and sign-off evidence.
